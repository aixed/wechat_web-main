## 访问密钥

首次输入任意非空密钥会创建独立用户。后续使用相同密钥登录，即可继续管理该用户启动的微信。密钥最多 256 个字符；`access_users` 使用密钥 SHA-256 摘要认证，`hook_profiles.access_key` 按每行配置明文保存所属用户的密钥，便于在本地数据库中直接查看和判断归属。

升级前已有的微信归到 `config.yaml` 中原 `web_access_key` 对应用户。新密钥的微信列表为空，不能查看或操作其他密钥的账号、二维码、联系人、聊天记录和附件。浏览器不同标签页分别保留登录凭据，切换一个标签页的密钥不会切换其他标签页的用户。

用户和微信归属数据库：`backend/db/access_users.sqlite3`，使用标准 SQLite，默认无数据库密码。

| 表 | 内容 |
| --- | --- |
| `access_users` | 用户 ID、密钥 SHA-256 摘要、创建及登录时间 |
| `user_accounts` | 按部署环境记录用户与微信实例、协议会话的唯一归属 |
| `hook_profiles` | `access_key` 明文所属密钥，以及用户的 RDV、启动端口、进程 ID、代理及启动参数 |
| `access_metadata` | 原账号归属迁移标记 |

新增用户的聊天缓存保存在 `backend/db/users/<用户ID>.sqlite3`。原用户继续使用迁入 `backend/db/` 的已有缓存。升级时停止旧后端后重新启动，旧 `backend/.sqlite_cache/` 会自动迁移；现有同名文件不会被覆盖，冲突的旧文件保留在新目录中的 `legacy/` 备份目录。请整体备份 `backend/db/`；删除用户归属数据库会丢失新用户的微信关联。服务器 AI/MCP 全局配置仍由原配置密钥用户管理。

旧版本数据库自动增加 `access_key` 字段：原配置密钥对应的记录会立即补齐，其他用户下次使用原密钥登录时自动补齐。密钥摘要无法反解为明文，因此没有已知密钥的旧记录会暂时留空。登录时同时从本人的配置恢复缺失的账号归属；若用户身份行丢失，可凭配置中的明文密钥恢复原用户 ID，继续使用原缓存。已有的其他用户归属不会被覆盖，已删除的账号不会重新恢复。明文密钥列不加入配置接口的返回内容；数据库文件保持本地存储，不提交到 Git。

## Hook 启动和设置

本地或远程 Hook 模式下，点击顶部“启动微信”新增实例并获取二维码。新微信自动生成 `01000000`～`7fffffff` 范围内的 8 位小写十六进制 RDV，并持久保存；以后启动同一微信会复用其 RDV。

点击左侧待登录卡片，右侧展示该微信的二维码，当前卡片高亮。点击二维码可刷新；待登录期间每 2 分钟自动刷新一次。未登录账号的头像显示为灰色，保存过微信 ID 不代表当前在线。

右键卡片可选择“退出登录”结束该实例进程，同时清空二维码并停止刷新。从未成功登录的实例会自动移除卡片和启动记录；曾成功登录的账号保留卡片、RDV 和本地记录，便于下次登录。“删除”会先显示不可撤销警告，确认后关闭实例，清理该微信的数据库记录、智能回复配置、附件数据及启动参数。其他微信的记录及共用附件会保留。

右上角齿轮可修改 RDV，并使用滑动开关启用代理，填写地址、端口；“更多设置”可填写代理账户和密码。点击“确定并重新启动”后，程序核对原实例的端口、RDV 和进程 ID，关闭原实例，使用新参数调用管理器 `mgr_port`（默认 29999）的 `/StartWechat`，然后轮询获取二维码。关闭代理后不会向管理器传入代理参数。

关闭成功以管理器确认原微信进程退出为准。部分管理器会把 Windows 的 `TIME_WAIT` 残留连接也算作端口占用；启动前会结合微信进程列表和 Hook 主机实际的 TCP 监听状态核实。仅在没有微信使用该端口、且连接明确被拒绝时忽略残留占用；仍有进程、其他服务监听或网络状态无法确认时会阻止重复启动。

终止微信使用该实例的当前微信端口：`http://<host>:<当前微信端口>/TerminateThisWeChat`，请求体为空对象。管理端口只用于启动、进程和端口核对；退出、删除、修改设置后的重启均使用实例端口终止原进程。

重复点击普通启动会复用已运行的原实例。管理器超时时不会自动重放启动请求；保留的 RDV 和端口用于下次核对并接续。Hook 和协议登录入口保持分开。
