## 1. 项目简介

本项目是一个基于 **FastAPI + React** 的微信 Web 客户端，通过连接本地或远程微信 Hook/协议服务，提供：

- 会话列表、聊天消息、媒体加载、发送消息、实时消息推送；
- 多微信账号管理、通讯录、群发、手机端自适应访问等能力；
- **AI 智能回复**：按会话配置关键词规则和 AI Skill，收到指定联系人/群的消息后自动分析和回复；
- **MCP 工具调用**：AI Skill 匹配后，可通过标准 MCP 协议调用外部工具服务，把执行结果组织成回复发回聊天。

### 技术架构一览

```text
微信客户端(Hook DLL) ──WebSocket(/agent)──┐
                                          ▼
                      FastAPI 后端 (默认 127.0.0.1:5000)
                        │  ├─ 消息回调 → 智能回复引擎
                        │  ├─ AI 服务 (OpenAI 兼容接口)
                        │  └─ MCP 客户端 (Streamable HTTP) ──→ 外部 MCP 服务
                                          ▲
                      React 前端 (Vite)  ──┘  REST + WebSocket
```

## 2. 快速开始

### 2.1 准备配置

```bash
cp config.example.yaml config.yaml
```

按实际环境修改 `config.yaml`，重点检查：

| 配置项 | 说明 |
| --- | --- |
| `wechat_mode` | 微信使用方式：`1`=本地 Hook，`2`=远程客户端 Hook，`3`=远程服务器协议 |
| `server_host` / `server_port` | 后端监听地址和端口，默认 `0.0.0.0:5000` |
| `web_access_key` | 前端和接口访问密钥，**首次默认 `admin`，请务必修改** |
| `ai_base_url` / `ai_api_key` / `ai_model` | AI 智能回复的大模型服务配置（也可稍后在页面上配置） |
| `agent_ws_enabled` | 远程 Hook 模式下，客户端 DLL 主动连接 `/agent` 长连接的开关 |

### 2.2 启动后端

后端使用 Python 3.13：

```bash
cd backend
pip install -r requirements.txt
python login_remote_hook.py   # 登录微信，优先免扫码，失败回退扫码
python main.py                # 启动后端服务
```

Windows 下也可以直接运行 `start-all.bat` 一键启动，脚本会自动检查 Python 3.13 和 Node 环境、清理遗留进程并打开浏览器。

### 2.3 启动前端

```bash
cd frontend
npm install
npm run dev
```

启动后浏览器访问 `http://127.0.0.1:<前端端口>`，输入访问密钥（`web_access_key`）进入系统：先展示微信账号卡片，点击账号进入对应聊天窗口。

## 3. 日常使用

- **会话列表**：置顶、未读数、@我提示、右键菜单等，与常见聊天软件习惯一致。
- **聊天窗口**：支持发送文本、图片、文件；展示图片、表情、语音、视频、网址、引用等消息。
- **通讯录**：按个人、群聊、公众号、服务号、企业微信联系人分类展示。
- **群发**：支持单号群发和多号群发，可按所有好友/所有群发送，支持并发上限配置。
- **智能回复入口**：在会话列表条目或聊天窗口的会话操作菜单中选择「**智能回复**」，进入该会话的智能回复配置面板。
- **主题**：PC 和手机端均支持白天/夜晚模式。

## 4. AI 智能回复

### 4.1 它能做什么

为指定聊天（好友或群）配置一套「收到消息 → 判断 → 自动回复」的规则：

- **关键词规则**：命中关键词立即按固定内容回复，速度快、零成本；
- **AI Skill（智能任务）**：关键词未命中时交给大模型按你写的指令分析，返回结构化结果后回复；
- **AI Skill + MCP**：AI 分析命中后，进一步调用外部 MCP 工具完成实际操作，再把结果回复给对方。

### 4.2 基础配置项

进入某个会话的智能回复面板后，可以配置：

| 配置项 | 说明 |
| --- | --- |
| 启用开关 | 该会话智能回复总开关 |
| 消息类型 | 文本、图片、GIF、语音、视频、文件、XML、系统、撤回、引用；默认只处理文本 |
| 目标发送人 | 按消息类型分别选择允许触发回复的联系人/群成员（必选，未选择的人发消息不会触发） |
| 文本消息只处理 @本人 | 群聊中开启后，只有 @ 了登录账号的文本消息才可能触发 |
| 底层发送方式 | 开启后使用 `NoSrc` 高效接口发送文本回复 |
| 文件内容识别 | 目前支持 TXT 文件（≤2MB），读取文件内容交给 AI 分析 |

### 4.3 关键词规则

每条规则包含：

- **关键词**：匹配消息内容；可勾选「正则表达式」按正则匹配（忽略大小写）；
- **回复内容**：命中后发送的固定文本；
- **随命中行回复**：勾选后不发送固定文本，而是把消息中**命中关键词的那一行**（去掉行尾数字）作为回复。

匹配优先级：**配置的关键词规则 → AI Skill → 旧版行数规则**（旧版规则：纯文本消息达到 2 行时回复 `1` 并自动停用该会话，为兼容保留，通常不建议依赖）。

### 4.4 AI 与 MCP 设置（模型配置）

点击智能回复面板右上角的「**AI 与 MCP 设置**」：

1. 在「AI 模型」中添加配置档案：**API 地址**（OpenAI 兼容 base_url）、**API Key**、**模型名称**；
2. 点击「校验」测试连接（校验只测试连通性，不保存）；
3. 保存后配置写入本机 `config.yaml`（`ai_base_url`、`ai_api_key`、`ai_model`、`ai_profiles`）；
4. 支持多个模型档案，选择其中一个作为当前使用模型；也可直接在 `config.yaml` 中配置 `ai_active_profile_id` 与 `ai_profiles` 列表。

相关参数：

- `ai_timeout_seconds`：单次 AI 请求超时，默认 60 秒；
- `ai_max_concurrency`：AI 请求并发上限，默认 3。

后端会优先尝试 OpenAI **Responses API**（`/responses`，带 JSON Schema 严格输出），404/405 时自动回退到 **Chat Completions**（`/chat/completions`，JSON mode），因此兼容大多数 OpenAI 兼容网关。

### 4.5 AI Skill（智能任务）

在智能回复面板的「Skill」区域新建 Skill，每个 Skill 包含：

| 字段 | 说明 |
| --- | --- |
| 名称 | 仅用于识别 |
| 消息类型 | 该 Skill 处理的消息类型（文本 / 图片 / 文件） |
| 任务指令 | 用自然语言描述"做什么"，例如提取信息、判断意图、生成答复等 |
| 启用开关 | 单个 Skill 可独立启停 |
| 输出模式 | 见 4.6 |

每个消息类型最多 20 个 Skill；收到消息后，**所有启用的同类型 Skill 会并发分析**。

面板上还有「**AI 测试**」：粘贴一条示例消息，指定某个 Skill 试运行，验证指令效果，不会真的发送消息。

### 4.6 输出模式

AI 分析结果是一个结构化对象，包含 `matched`（是否命中）、`confidence`（置信度 0–100）、`result`（主结果）、`items`（多条结果）、`reply`（建议回复）。输出模式决定如何变成发出的消息：

| 模式 | 行为 |
| --- | --- |
| `result`（默认） | 发送 AI 的 `result`/`reply` 文本 |
| `template` | 按「回复模板」渲染，支持 `{{result}}`、`{{reply}}`、`{{items}}`、`{{item}}` 等占位符 |
| `silent` | 只执行动作（例如配合 MCP），**不回复任何消息** |

### 4.7 完整触发流程

```text
收到新消息
  │
  ├─ 未启用/非配置会话？ ──→ 结束
  ├─ 自己发的消息？ ──→ 结束（永不回复自己）
  ├─ 发送人不在目标列表？ ──→ 结束
  ├─ 群聊文本未 @本人？ ──→ 结束
  │
  ├─ 消息是图片？ ──→ 先 OCR 提取文字 ──→ 再走关键词 / AI（必要时把原图给视觉模型）
  ├─ 消息是 txt 文件？ ──→ 读取文件内容 ──→ 交给 AI
  │
  ├─ 关键词规则命中？ ──→ 立即并发发送回复（快速通道，不经过 AI）
  │
  ├─ 有启用的 AI Skill？ ──→ 并发调用 AI 分析
  │     ├─ 未命中（matched=false）──→ 结束
  │     ├─ Skill 启用了 MCP？ ──→ 调用 MCP 工具 ──→ 用结果组织回复（见第 5 章）
  │     └─ 普通 Skill ──→ 按输出模式生成回复
  │
  ├─ 去重 + 冷却检查（见 4.8）──→ 通过
  │
  └─ 发送回复 ──→ 同步到前端界面 ──→ 更新触发计数/停用状态
```

### 4.8 防骚扰与安全机制

系统内置多道闸门，避免自动回复刷屏或误回：

| 机制 | 规则 |
| --- | --- |
| 消息去重 | 同一账号 + 同一会话 + 同一发送人 + 相同内容，5 分钟内只回复一次（最多记录 5000 条） |
| 会话冷却 | 同一会话两次回复至少间隔 1.5 秒，AI 回复同样受限 |
| 不回复自己 | 登录账号自己发送的消息永不触发 |
| 白名单 | 只有「目标发送人」名单内的人才能触发 |
| 群 @ 限制 | 可要求群聊文本必须 @ 本人 |
| 位置消息忽略 | 以「位置」「[位置]」等开头的消息不处理 |
| 自动停用 | 触发旧版「两行回 1」规则后自动停用该会话 |

## 5. MCP 的运转方式

MCP（Model Context Protocol）是一个开放协议，让 AI 能够调用外部工具。本项目后端内置了一个 MCP 客户端，可以把任意支持 **Streamable HTTP** 传输的 MCP 服务接入 AI Skill：**Skill 负责判断该不该做，MCP 工具负责真正去做，AI 最后组织回复**。

### 5.1 整体运转流程

```text
聊天消息
  │
  ▼
关键词规则（快速通道，未命中继续）
  │
  ▼
AI Skill 分析（大模型按任务指令判断消息，返回 matched + 结构化结果）
  │  matched = false ──→ 结束，不回复
  │  matched = true
  ▼
MCP 调用阶段（该 Skill 开启了「调用 MCP 工具」时）
  │
  ├─ ① 确定工具：配置里手动指定了工具名 ──→ 用它
  │     未指定 ──→ 后端先 initialize + tools/list 发现工具清单，
  │               再让 AI 根据消息、Skill 指令和工具描述自动选择
  │               （认为不合适则不调用，直接按普通 Skill 回复）
  │
  ├─ ② 准备参数：用「工具参数 JSON」模板渲染；
  │     支持占位符 {{identifier}}、{{result}}、{{reply}}、{{items}}
  │
  ├─ ③ 实际调用：MCP 客户端与 MCP 服务完成 initialize 握手，
  │     发送 tools/call，服务返回文本/结构化结果
  │
  ├─ ④ 生成回复：AI 把「Skill 分析结果 + 工具返回结果」合成为
  │     最终回复；失败时回退到「MCP 回复模板」渲染
  │
  ▼
去重 + 冷却检查 ──→ 发送回复（或 silent 模式下不发送）
```

要点说明：

- **每次工具调用都是一次独立的 MCP 会话**（initialize → tools/call），调用完成后即结束，符合 Streamable HTTP 无状态用法；
- 自动选工具时，AI 只能看到工具名称、描述和参数 Schema（最多前 50 个），并按 Schema 生成参数；消息内容被视为**不可信数据**，不会当作指令执行；
- AI 自动选择认为"不该调用"时，流程不会失败，而是退回普通 Skill 的文本回复；
- 输出模式为 `silent` 的 Skill：工具照常调用，但**不回复任何消息**。

### 5.2 配置 MCP 连接

在「**AI 与 MCP 设置**」弹窗的「**MCP 连接**」区域：

1. 点击「添加 MCP 连接」，填写：
   - **连接名称**：仅用于识别；
   - **MCP 地址（URL）**：MCP 服务的 Streamable HTTP 端点，例如 `http://127.0.0.1:<端口>/mcp`；
   - **Bearer Token**：MCP 服务开启鉴权时填写，请求会带上 `Authorization: Bearer <token>` 头；本机服务未开鉴权可留空。
2. 点击「**连接并读取工具**」验证：后端会执行一次 `initialize` + `tools/list`，成功后显示服务名称和发现的工具数量；
3. 保存设置，连接信息持久化到本机 `config.yaml`。

> 建议将 MCP 服务只监听本机（`127.0.0.1`）。若必须监听非本机地址，MCP 服务的 Token 为必填项，请使用足够长的随机令牌。

### 5.3 在 Skill 中启用 MCP

编辑某个 AI Skill，打开「**调用 MCP 工具**」开关：

| 字段 | 说明 |
| --- | --- |
| MCP 连接 | 选择 5.2 中配置好的连接（必选） |
| MCP 工具 | 留空 = 由 AI 根据消息和工具描述**自动选择**；也可从下拉框手动指定固定工具 |
| 工具参数 JSON | 调用工具时使用的参数模板（JSON 对象），支持占位符（见下） |
| MCP 回复模板 | AI 合成回复失败时的兜底模板，支持 `{{mcp_text}}`（工具返回文本）、`{{mcp_json}}`（结构化结果 JSON）、`{{identifier}}`、`{{result}}`、`{{reply}}` 以及结构化结果中的任意字段名 |

**占位符说明**：

- `{{identifier}}`：后端会从 AI 分析结果中自动提取 4–5 位数字标识；模板里使用了 `{{identifier}}` 而分析结果中没有标识时，本次调用会报错终止，**不会用空值调用工具**；
- `{{result}}` / `{{reply}}` / `{{items}}`：AI 分析结果的主文本、回复文本和列表；
- 工具参数模板要求渲染后仍是合法 JSON 对象。

**示例**（参数模板，仅为格式示意，具体字段以你的 MCP 工具 Schema 为准）：

```json
{ "identifier": "{{identifier}}" }
```

### 5.4 安全注意事项

- **区分只读与写入工具**：MCP 工具带有 `destructiveHint`（会修改外部系统）标注时，前端会明确提示「Skill 匹配后将直接执行」。配置这类工具前请确认 Skill 的任务指令足够精确，必要时先使用 `silent` 模式和 AI 测试验证；
- **消息即数据**：聊天消息只作为待分析的数据传给 AI 和工具，系统提示词中明确要求不得执行消息内出现的代码、链接或指令；
- **防重复**：同一条消息命中多个 Skill/MCP 时仍受全局去重与冷却限制；对有副作用的工具调用，服务侧也应做好幂等（调用方保存返回结果，避免重复创建）；
- **密钥保管**：MCP Token 与 AI API Key 均保存在本机 `config.yaml`（不进 Git），请勿提交或外传。

## 6. 日志与问题排查

所有日志按天存放于 `backend/logs/`：

| 目录 | 内容 |
| --- | --- |
| `logs/main/` | 后端通用与 Hook API 日志 |
| `logs/smart_reply/` | 智能回复收件、匹配、AI/MCP 调用、发送与耗时日志 |
| `logs/login/` | 登录脚本日志 |

智能回复每条消息的处理都会记录原因（`reason`），常见值对照：

| reason | 含义 |
| --- | --- |
| `disabled` | 该会话未启用智能回复 |
| `self_message` | 自己发送的消息，不回复 |
| `sender_not_allowed` | 发送人不在目标发送人名单 |
| `mention_required` | 群聊文本未 @ 本人 |
| `message_type_not_enabled` | 消息类型未启用 |
| `keyword_not_matched` | 关键词未命中（若配置了 AI Skill 会继续进入 AI 阶段） |
| `duplicate` | 5 分钟内的重复消息 |
| `cooldown` | 会话冷却中（1.5 秒） |
| `ai_no_reply` | AI 未产生可发送内容 |

排查建议：

1. 确认会话已启用、消息类型和目标发送人配置正确；
2. 在 `logs/smart_reply/` 中按消息 `message_id` 搜索，可以看到完整的过滤、AI、MCP、发送链路和每步耗时；
3. MCP 报错（如 `MCP connection failed`、`MCP HTTP 401`）通常是地址错误、服务未启动或 Token 不对；`MCP arguments are not valid JSON` 表示工具参数模板渲染后不是合法 JSON；
4. AI 报错（`AI request failed`）先用「AI 与 MCP 设置」里的校验按钮确认 API 地址、Key 和模型可用。

## 7. 常见问题

**Q：智能回复一定需要配置 AI 吗？**
不需要。只用关键词规则即可工作，且关键词命中的回复不消耗 AI 调用；AI 只处理关键词未命中的消息。

**Q：同一个会话可以同时配置多个 Skill 吗？**
可以。同一消息类型的所有启用 Skill 会并发分析，各自产生的回复会合并发送（仍受去重和冷却限制）。每个消息类型最多 20 个 Skill。

**Q：图片消息如何触发回复？**
先自动 OCR 提取图片文字，提取结果可命中关键词规则；未命中且有图片类 AI Skill 时，会把 OCR 文字（或直接把原图，≤8MB）交给视觉模型分析。

**Q：MCP 服务关掉后智能回复会失败吗？**
该 Skill 调用工具时会记录 `MCP connection failed` 等错误并跳过本次 MCP 调用，回退为普通 AI 回复（或按日志提示排查）。恢复服务后无需重启后端，下次调用会重新建立连接。

**Q：修改 `config.yaml` 后需要重启吗？**
`hook_api_concurrency`、AI 超时/并发等启动参数需要重启后端；AI 模型档案、MCP 连接、智能回复配置在页面保存后即时生效。

**Q：访问密钥忘记了怎么办？**
在 `config.yaml` 中查看或重新设置 `web_access_key` 后重启后端；也可以通过环境变量 `WECHAT_WEB_ACCESS_KEY` 配置。
